# 월별 케이팝 티어 페이지

주소: `/music/tiers/`. 음악 주제 페이지(`/topics/music/`)에서 진입합니다.

블로그의 월별 평가·한줄평을 공개하고, 방문자가 같은 곡 목록으로 자기 티어를 만듭니다. 기존 Astro 레이아웃과 테마 색상을 재사용합니다. 외부 서버·호스팅·추가 npm 의존성은 없습니다.

## 들어 있는 기능

- 블로그 티어 / 내 티어 / 공유받은 티어 보기
- S–D, 미평가 배치. PC 드래그, 터치·키보드용 곡 상세창, 같은 티어 내 앞·뒤 이동
- 블로그 평가와 비교, 되돌리기, 초기화
- 월별·곡 목록 버전별 브라우저 자동 저장
- 배치를 담은 공유 링크, JSON 가져오기·내보내기
- PNG 결과 이미지. 변환이 불가능한 환경에서는 SVG로 저장
- Pages CMS에서 월·곡·평가·한줄평·이미지·공식 링크 편집

## 월별 목록 관리

Pages CMS → **음악 · 월별 케이팝 티어**에서 월을 추가합니다. 데이터는 `src/data/kpop-months.json`에 저장됩니다. `published`를 켜고 main에 저장하면 기존 GitHub Pages 배포를 통해 공개됩니다.

1. `month`: `2026-10`처럼 발매 월 입력. 중복 월은 빌드 오류입니다.
2. `revision`: 최초 `1` 등으로 지정. 곡 추가·삭제, ID 교체 시 올립니다. 한줄평·평가 변경에는 유지합니다. 버전 변경 시 이전 링크는 거부되며 방문자는 새 버전에서 다시 평가합니다.
3. `demo`: 실제 곡·평가를 입력한 월에서는 끕니다. 실제 공개 월이 생기면 시연용 월은 화면에서 제외됩니다.
4. `tracks`: 곡 ID, 제목, 아티스트, 실제 발매일, 티어, 한줄평 입력. 같은 티어에서는 목록 순서대로 표시됩니다. 미청취 곡은 `unranked`입니다.
5. `cover`: `/img/` 내부 이미지 선택. `listenUrl`: 공식 YouTube·Spotify·벅스 HTTPS 링크 선택. 앨범 이미지가 없으면 색상과 제목으로 표시합니다.

현재 공개 목록은 2026년 10월 실데이터입니다. 수집 범위·곡별 출처·중복 제거 기준은 `docs/music/kpop-2026-10-sources.json`에 기록합니다. 모든 곡은 미평가로 시작하며 임의의 한줄평은 넣지 않았습니다. 테스트의 가상 데이터는 `tests/fixtures/`에만 남아 공개 페이지에 포함되지 않습니다.

월별 전체 발매곡을 자동 수집하지 않습니다. 관리자가 선정한 목록이 기준입니다. 타이틀곡만 다룰지, 수록곡·OST·일본 발매곡을 포함할지는 소개에 적고 매월 같은 기준을 적용하는 편이 좋습니다.

## 저장과 공유

내 티어는 해당 브라우저에만 저장됩니다. 기기 간 자동 동기화·방문자 투표 집계는 없습니다. 공유 링크는 URL fragment에 월·곡 목록 버전·순서만 포함하고 한줄평은 포함하지 않습니다. 링크를 여는 것만으로 내 저장본이 바뀌지 않습니다. `내 티어로 가져오기`를 누르면 교체되며, 되돌리기로 직전 저장본을 복구할 수 있습니다.

브라우저 저장을 사용할 수 없는 경우 안내를 표시합니다. 파일 저장으로 백업하세요. 이미지 출력에는 제목·아티스트·티어와 색상 카드를 넣으며 앨범 이미지 자체는 포함하지 않습니다. 긴 텍스트는 이미지에서 줄여 표시합니다. 방문자 배치는 서버에 수집하지 않습니다.

CMS의 비공개 월은 페이지 데이터에서 제외되지만 공개 Git 저장소의 파일에는 남습니다. 개인정보를 넣지 마세요.

- 상태 이동·공유 인코딩·잘못된 데이터·목록 버전·외부 URL·캘린더 검증 통과
- Pages CMS 기존 글 컬렉션 계약 보존 및 별도 JSON 설정 검증 통과
- Chrome 실제 조작: 내 티어 전환, 곡 이동, 자동 저장·새로고침 복원, 월 전환, 비교, 공유 링크 열기, PNG 다운로드 확인

실제 iPhone Safari의 터치 조작·파일 저장·클립보드, 실제 Pages CMS 계정에서 저장→GitHub Pages 발행은 미검증입니다. 새 데이터는 빌드 시 검증되며 잘못된 ID·날짜·중복 월·외부 이미지 경로·지원하지 않는 음원 URL은 배포 전에 거부됩니다.

## 발행과 운영

`main` 변경 시 기존 GitHub Pages 워크플로가 테스트·Astro 빌드·배포를 실행합니다. 새 곡 목록이나 평가를 저장한 뒤 GitHub Actions의 배포 완료 상태를 확인하세요.

공개 주소: https://bunnykey.github.io/music/tiers/

Pages CMS 설정의 근거:
- https://pagescms.org/docs/configuration/content/list/
- https://pagescms.org/docs/configuration/content/fields/

기존 flora·seeds·nursery, 로컬 편집기, Notion 동기화 계약은 유지합니다. 월별 평가는 기존 글 컬렉션과 별도 JSON 파일에서 관리합니다.

## 공개 평가 반영

방문자는 **내 티어 만들기**에서 곡을 배치하고 곡 상세의 **내 한줄평**을 입력할 수 있습니다. 둘 다 브라우저에 저장됩니다. 공유 링크에는 배치만 포함하며 한줄평은 포함하지 않습니다. 개인 JSON 백업과 **공개 평가용 파일**에는 한줄평도 들어갑니다.

블로그 주인이 공개 평가용 파일을 받았으면 아래 명령으로 기존 곡 정보와 다른 월을 유지한 채 티어·한줄평만 적용합니다.

```sh
node scripts/music/import-kpop-ratings.mjs /path/to/kpop-2026-10-public-ratings.json
npm test
npm run build
```

스크립트는 월·곡 목록 버전·전체 곡 ID·한줄평 길이를 검사합니다. 파일 다운로드만으로 공개 블로그가 바뀌지는 않습니다. 내용 확인 후 기존 GitHub Pages 발행 절차로 반영합니다. Pages CMS에서도 개별 티어·한줄평을 계속 수정할 수 있습니다.
